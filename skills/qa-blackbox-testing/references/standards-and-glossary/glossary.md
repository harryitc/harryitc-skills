# QA / Black-box Testing Glossary

> **Owner:** QA/QC Leader (designate) · **Reference status:** Draft for pilot · **Last reviewed:** 2026-10-26


| Thuật ngữ | Định nghĩa dùng trong toolkit |
|---|---|
| Test Basis | Tài liệu/thông tin dùng làm căn cứ phân tích và thiết kế test, ví dụ requirement hoặc API contract. |
| Test Condition / Coverage Item | Khía cạnh/điều kiện cần xác minh được xác định từ Test Basis. |
| Test Scenario | Mô tả tình huống/hành vi cần kiểm thử ở mức tổng quát. |
| Test Case | Các điều kiện, preconditions, steps, data và expected result đủ để thực thi/xác minh. |
| Test Data | Dữ liệu đầu vào hoặc trạng thái dữ liệu dùng cho test. |
| Expected Result | Kết quả mong đợi có căn cứ và có thể xác minh. |
| Equivalence Partitioning (EP) | Chia miền dữ liệu/điều kiện thành các lớp được kỳ vọng xử lý tương tự. |
| Boundary Value Analysis (BVA) | Thiết kế test quanh các giới hạn của miền giá trị đã xác định. |
| Decision Table Testing | Dùng bảng thể hiện tổ hợp điều kiện và hành động/kết quả. |
| State Transition Testing | Kiểm tra hành vi khi entity thay đổi trạng thái do sự kiện/hành động. |
| Requirement Coverage | Mức độ requirement/rule đã được map tới các case phù hợp theo tiêu chí đã định. |
| Traceability | Khả năng truy ngược giữa source requirement, coverage item, Test Case, execution và defect. |
| Test Type | Nhóm mục tiêu kiểm thử, ví dụ functional hoặc permission. |
| Design Technique | Cách thiết kế/định chọn dữ liệu và case, ví dụ EP/BVA. |
| Priority | Thứ tự tương đối nên thực thi Test Case. |
| Severity | Mức độ ảnh hưởng của defect đã phát hiện. |
| Review Status | Trạng thái review/phê duyệt Test Case. |
| Execution Status | Trạng thái kết quả chạy test. |
| Assumption | Giả định tạm cần xác nhận; không phải quy tắc đã phê duyệt. |
| Needs Clarification | Thiếu/mâu thuẫn nguồn khiến chưa thể xác định expected result đáng tin. |
| Observability | Khả năng kiểm chứng kết quả từ UI, phản hồi, trạng thái hoặc nguồn được phép quan sát. |
| Black-box Testing | Thiết kế/đánh giá test dựa trên hành vi được đặc tả mà không tham chiếu cấu trúc nội bộ của phần mềm. |

Nếu dự án đã có glossary được phê duyệt, dùng định nghĩa của dự án hoặc ghi rõ mapping khác nhau.
